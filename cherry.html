樱桃 AI

Windows 办公助手。引擎是我写的；办公界面是团队一起做的。

樱桃 AI 装在 Windows 上，用来把一件事办完：调工具、点桌面、按需要读技能说明、记住长期习惯。客户端管窗口、账号，以及把引擎拉起来。Agent 引擎里，一轮对话从哪开始、工具从哪出去、桌面怎么点、记忆写在哪，都在这里。

另外我做了局域网房间，和对话里的「发给电脑」。房间那一页也有同事一起改过。语音控制整页、拓展目录界面，主要是同事做的，下面不写成我的作品。

调用大模型的密钥放在服务器上，不放在用户电脑里。要打开浏览器时，窗口是客户端开的，引擎只发请求、把结果收回来。

上线之后

  • 2026 年 7 月 28 日客户端开始接入，现已在生产环境使用。办公主界面仍是同事的。
  • 6 月起，模型密钥只放在公司网关。用户电脑不再持有厂商密钥。
  • 9 月 11 日起，日常对话不再做向量检索。长期记忆改成本机一份文件，只有这一轮成功做完才写入。
  • 11 月 9 日局域网房间和「发给电脑」上线。

怎么叠在一起

三层各管各的。上面是客户端，中间是引擎，底下是引擎要调用的东西。局域网把活送到对面那台电脑，由对面自己的引擎跑，不走你这边正在进行的工具循环。

一轮对话

客户端把话送进来（Pipe），或直接在命令行问。引擎先记下这一轮，再带着记忆问模型。要用工具，就从同一处出去，结果交回后再问，直到不用了。代码里还有「本地步骤短路」：命中写好的步骤可以不经过模型。这条默认关着，日常对话不走。

  • 工具都从同一处出去：先看路径对不对、这件事能不能做，再真正执行。
  • 点桌面：主模型只说出要点的窗口和控件，报点模型补上像素坐标，再交给 Windows-MCP。不是另开一个桌面小助手去点。点了界面没变化就停。正在点的时候可以按 F9 停掉。
  • 技能说明不会每句话都自动塞进来。先搜到，需要时再读一遍说明，然后按说明去调工具。
  • 很短的命令当场等结果。跑得久的先等最多约 30 秒，超时就放到后台；做完之后，如果这轮还在，再把结果送回来。
  • 长期记住的东西写在用户电脑上的 MEMORY.md 里，不是向量库。每次开口会带上这份文件里截过的一段。只有这一轮成功做完，才写入三类：你纠正过的说法、一件可以长期记的事实、一个问题最后是怎么解决的。
  • 可以派一个只干一件事的子任务，等它做完再收回来，也可以先放在后台。要立刻停，走停止。

上下文怎么进

每一轮问模型前，提示词按层拼好。身份和规则每次都在；记忆和当前技能粘在这一轮；待办和会话会变；工作区默认不整包塞进来，需要时再带或再搜文件。技能全文同样：先搜到，要用才读一遍。

工具怎么出去

模型只提出要用哪一种能力。真正动手前，都经过同一道闸：先校正路径，再看能不能做。本机日常以放行为主；明确不允许的直接拒绝并交回模型。高风险或高成本会先问客户端，等确认期间不能插话。

点桌面

网页不走这条：窗口由客户端开，引擎只发请求。点 Windows 界面才走桌面。非视觉主模型不能点。

人怎么插手

Agent 跑着时，人还能做四件事。子任务不能向用户提问，要问就交回主轮。

怎么收口

一轮结束必须有明确状态，不能假装做完。计划就是模型自己写的待办，没有第二套规划状态机。

局域网

同一局域网里，可以把任务交给另一台电脑上的助手。对面用那台电脑自己的引擎跑，不经过本机这一轮的工具循环。房间挂在常驻进程上，不挂在每一路对话进程里。

对照过什么

引擎是自己写的。下面是和常见助手的对照：哪些写进了提交记录，哪些只当产品看过、没有当底座。

对照谁 我拿了什么 我没跟着走
OpenClaw 3 月仓库里提交过它的构建产物；技能包里还留着它的元数据格式。 没有一直绑在它的运行时上，核心是自己写的。
Cursor 待办怎么写、用户插话怎么进当前这一轮、子任务的状态怎么报。 不是做 IDE 插件，是做装在 Windows 上的助手。
Claude Code 长期记忆写成一份本地文件；改文件用补丁；跑得久的命令先等一小会，超时再放到后台。 不是做它那种终端产品，也不走它的订阅。
Harness 自己写了一层编排：一轮对话何时开始、做到哪一步、何时结束、子任务怎么收口。代码里就叫这个名字。 没有去套别人现成的 Harness 包。
Windows-MCP 点桌面走这套接口。 主模型出目标，报点后再点。点了没反应就停，避免瞎点。
字节（豆包） 网关里接过豆包，当一种能调用的模型。 不是 Agent 框架。默认配置里后来还拿掉过。
Grok 等产品 日常当成品助手对照，看对话和工具怎么走。 提交记录里没有把它们的代码当底座。LangChain、Dify 同样没有。

边界

  • 办公界面不是我独做的。语音控制整页、拓展目录界面，主要是同事的。局域网房间页也有同事一起提交，我做的是引擎，以及「发给电脑」这条链路。
  • 模型做出的文件，引擎只记下在哪，不拿来展示，也不在电脑上当程序跑。这不是一套把所有生成网页都隔离开的沙箱。
  • 日常工具放行比较多。需要确认的时候会问客户端。不是每一步都弹窗，也不是完全不问。
